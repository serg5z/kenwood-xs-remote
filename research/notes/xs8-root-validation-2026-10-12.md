# ROOT power and CD transport: physical report received 2026-10-12

This note records operator-supplied physical observations on the Kenwood KR-V6070 and connected CD changer. The exact experiment date and individual BUSY/DATA edge captures, service replies, and photographs were not supplied. The observations are physical reports, **not independently replayable from archived traces**. All TX values below are **current logical TX**; legacy TX is a second label for the same waveform, `logical = reverse8(~legacy)`. No RX bytes were reported for these trials, and no RX byte is inferred from a TX value.

| ROOT TX | Legacy TX | Reported setup and physical observation | Evidence limit |
|---|---|---|---|
| `0x52` | `0xB5` | Receiver POWER ON. The CD changer also powered on via the receiver's switched AC outlet. | The changer power change is explained by the outlet connection; this does not establish a separate XS8 power command to the changer. The earlier ROOT+CD+playing follow-up recorded no RX or visible action from `0x52` while the receiver was already on ([v18 follow-up](kenwood-xs-reverse-engineering-v18.md#L270-L276)). |
| `0x41` | `0x7D` | CD PLAY; the changer PLAY indicator lit. | The earlier ROOT+CD+playing sweep recorded no visible effect at `0x41`, consistent with a possible already-playing state but not proof of the state-dependent mechanism ([v18 ROOT matrix](kenwood-xs-reverse-engineering-v18.md#L250-L269)). No RX frame or playback audio result was supplied. |
| `0x41 → 0x9C` | `0x7D → 0xC6` | One service-side chained request with a requested 500 ms gap and approximately 506.7 ms measured from first TX end to second TX start. PLAY was followed by CD STOP. | This validates the observed PLAY-to-STOP result in that setup. It does **not** prove `0x9C` is a general KEY RELEASE or that it terminates every latched TRACK/SEEK operation. No underlying timestamped session log was deposited. |

The prior controlled notes already associated ROOT `0x9C` with CD STOP and delayed later-decoder RX `0xD6` in one CD test ([STOP comparison](kenwood-xs-reverse-engineering-v18.md#L302-L329)). No `0xD6` is claimed for the new chained trial. An older ROOT map reported that `0x9C` stopped continuous forward skipping started by `0xFC` ([copy 7](kenwood-xs-reverse-engineering%20copy%207.md#L437-L445)); the October 12 report did **not** repeat that hazardous sequence.

These observations establish effects in the reported receiver/changer states. They do not establish universal command safety, receiver acknowledgment, or a context-independent release primitive. The v18 ROOT matrix labels `0x41` PLAY and `0x52` POWER ON; this note keeps the state conditions and older negative observations visible rather than erasing either result.

For coverage classification, an earlier operator report in this project also stated that the Web Remote physically selected CD (`0x84`), TUNER (`0x82`), PHONO (`0x83`), and TAPE1 (`0x85`) successfully on this KR-V6070. The [source-selection document](../../docs/source-selection.md) lists their logical TX values and historical sweep evidence; it still presents a future validation checklist and is not itself a per-trial log. The earlier report supplies physical testimony, but no raw capture or complete display record is archived for those four trials.
